# Acpira

A chat shell for VS Code / Cursor that drives official agent CLIs (`grok agent stdio`, `devin acp`, `kimi acp`, or any ACP-compatible command) over [ACP](https://agentclientprotocol.com) (JSON-RPC over stdio). The shell owns UI, session organization, permission approvals, accounts, and context budget; model calls and agent execution stay in the CLIs.

## Commands

- `pnpm build` — host bundle (esbuild → `dist/extension.cjs`) + webview bundle (Vite → `dist/webview/main.{js,css}`)
- `pnpm typecheck` — two tsconfigs (`tsconfig.webview.json` covers `src/webview` + `src/shared` + the LAB in `src/lab` / `lab`; `tsconfig.host.json` the host; shared options in `tsconfig.base.json`); the root `tsconfig.json` is a solution file with `references` only, do not add `compilerOptions` to it. A source directory outside both `include` lists is neither type-checked nor alias-resolved by the IDE
- `pnpm test` — vitest; `test/fake-agent.ts` is a fake ACP agent built on the SDK that feeds events to `AcpSession` tests
- `pnpm probe grok [--auth] [--api-key-env VAR] [--import-local] [--image PATH] [--link PATH] [--embed PATH] [--elicit] [prompt]` — run `initialize` + `session/new` (+ one prompt, optionally with an inline image / `resource_link` / embedded `resource` block) against a CLI without VS Code; `--elicit` advertises form elicitation and prints / auto-answers `elicitation/create`. Use this first when debugging protocol issues
- `pnpm package` — build a `.vsix`

## Architecture

- `src/shared/transcript.ts` — normalized transcript shape, the single contract between host and webview; `SessionView` is the full state pushed to the webview
- `src/shared/protocol.ts` — `HostMsg` / `WebviewMsg` message contract; `src/shared/appearance.ts` — appearance axes
- `src/host/extension.ts` — `activate`: registers the activity-bar WebviewView, editor WebviewPanel, commands, settings listeners
- `src/host/bridge.ts` — one bridge per webview (HTML + CSP) owning one `SessionViewer`; events are batched over 30 ms before pushing
- `src/host/SessionManager.ts` — session hub (live processes, summaries); all webview actions enter here; must not import `vscode`. The active session is per viewer (`SessionViewer`, one per webview via `manager.attach(initial)`), so the sidebar and any number of editor tabs each show their own conversation over the shared list and process pool; `session` events go only to viewers showing that session, global events to all. `dropEmptyCurrent` leaves a session another viewer shows alone; `deleteSession` re-homes every viewer that was on it. The single-view API (`activeId` / `active()` / `handle()` / `newSession()`) is a lazily created default viewer for tests and scripts. `acpira.openInEditor` opens a fresh session unless given a session id
- `src/host/acp/` — `AgentRegistry` (built-in grok / devin / kimi + user-defined via `acpira.agents`, binary probing), `AgentProcess` (spawn + ndjson + `acp.client`), `AcpSession` (state machine: start → resume | load | new → ready, with auth_required / readonly / error states), `normalize.ts` (`session/update` → blocks, pure functions)
- Agent availability is live, never a reload-time snapshot: `AgentRegistry.probeAll` / `resolveBinary` re-verify cached paths (`access X_OK`) and notify `subscribe`rs when the available set changes; `SessionManager` re-pushes `agents` on that, polls every 10 s while `registry.missing()`, and `reprobe()`s on webview `ready` and window focus (`onDidChangeWindowState`). The first `probeAll` only sets the baseline (returns false). `AgentInfo.install` (`AgentDef.install` posix / windows / docs, custom agents via `acpira.agents.<id>.install`) feeds the settings page's install section (copy, `installAgent` → `bash -c` / `powershell -Command` in a terminal, docs link); the webview drops an agent's cached inventory when its `available` flips so the facts card rescans. Verify with `test/AgentRegistry.test.ts` and the SessionManager poll test
- `src/host/store/dataDir.ts` — `ACPIRA_HOME` or `~/.acpira`; `migrateOnce` merges a legacy `globalStorage` / SecretStorage tree in once per source (`.migrated` is JSON `{ sources: [...] }`; a legacy timestamp marker means "one unknown source", and a source whose UUIDs already exist in the destination is that one). VS Code and Cursor each have their own `globalStorage` but share `~/.acpira`, so the second IDE to start still brings its sessions / accounts along; nothing in the destination is overwritten and `index.json` is not copied (the store rebuilds it). Old files are left in place
- `src/host/store/TranscriptStore.ts` — `~/.acpira/sessions` holds `index.json` + `<id>.json` + `<id>/` (attachment blobs, content-hash names) + `trash/` (soft-deleted records during their undo window); record writes are debounced, every file is written tmp + rename. The directory is shared by every extension host (each VS Code / Cursor window), so `index.json` is a cache, never the truth: `syncIndex(mine, own)` re-reads it and reconciles with the record files (a file no index knows is loaded and summarized, an id without a file drops out; `mine` wins only for `own` ids — live or just patched — the disk for the rest), and `SessionManager` runs it debounced after changes plus `refreshIndex()` on webview `ready` and window focus so two windows converge without a reload. Verify with the two-store / two-manager tests in `test/TranscriptStore.test.ts` and `test/SessionManager.test.ts`
- Attachments: the webview turns pastes / drops / `@` picks into `Draft`s (`webview/chat/drafts.ts`, `Mention.tsx`) and sends them with the prompt; `host/acp/attachments.ts` (`preparePrompt`) writes images and dropped text to the session's blob dir and builds the `ContentBlock[]` — text → inline `image` → embedded `resource` (uri = blob path) → `resource_link` (Explorer / `@` files; image files among them are read and sent as `image`). The turn keeps `Attachment`s (blob name / uri only); the webview loads blobs from `InitState.blobBase` (the sessions dir as a webview URI, added to `localResourceRoots`). `@` search is `host/files.ts` (`findFiles` cached 15 s, fuzzy-scored host-side) answered over `searchFiles` → `files`
- `src/host/accounts/` — account layer. `types.ts` (`AccountProvider`: importLocal / login / spawnEnv? / authenticate?), `AccountStore` (metadata → `~/.acpira/accounts.json`, secrets → `SecretVault`: `FileVault` at `secrets.json` mode 600, `MemoryVault` in tests), `AccountManager` (import / terminal login / removal + two hooks for `AcpSession`), `devin.ts` (first provider). Must not import `vscode`. Cursor and VS Code share the directory; `accounts.json` is still a whole-file write from each host's memory (the session list is reconciled, see `TranscriptStore`).
- `src/webview/` — React UI: `ui/` primitives (Row / Disclosure / Button / Chip / Card / Popover / DropdownMenu / Command / Collapsible / RadioGroup / Switch / Dialog / Toast), `chat/` conversation components, `effects/` visual effects, `styles/` stylesheets (`index.css` entry → `tokens.css` design tokens + `@theme` map, `base.css` shell defaults, `prose.css` markdown, `motion.css` animation, `chat.css` conversation shapes Tailwind cannot express at one call site). Layering: single-element styles go in the TSX className; shared shapes are `@utility`; descendant rules sit in `@layer components` so a call-site utility still wins. Only rules that must beat the unlayered host webview stylesheet or `katex.min.css` stay unlayered (`base.css` code / kbd / focus, all of `prose.css`) — a layered rule loses to them regardless of specificity; `motion.css` is also unlayered because its rail / stream rules never compete with a utility. `ui/` primitives carry their own skins (`Switch` geometry lives in the `@theme` map, not in `settings.css`); wrappers that keep an internal ref merge the caller's with `ui/mergeRefs`
- `src/webview/` and `src/host/acp/` must never import `vscode`
- Transcript render budget: every stream chunk pushes the whole `SessionView` (fresh objects from `postMessage`), so `App` merges it with `shared/reuse.ts` — deep-equal subtrees keep their previous reference — and `AgentMessage` / `HistoryMessage` / `ToolCall` / `ReadGroup` / `Thought` / `Prose` / `Plan` are `memo`ized on those references. Anything that would defeat this must stay out: context values above `Thread` must not change per push (`HistoryContext` carries an `editable` flag, the composer props ride `HistoryComposerContext` only while an editor is open; `OpenToolFileContext` / `PlanDocumentContext` values are memoized, lists through `ui/useStableList`), and per-turn derived work caches by turn object (`usageBreakdown.ts`). Without this a 700-block session spent ~45 ms per frame on re-rendering during streaming and every fold toggle stuttered. Verify with `scripts/probe-fold-perf.ts --stream --cpu` against the LAB server (`lab/performance.preview.html`, profile `large`): streaming must hold ~16 ms frames with no long tasks

## Protocol gotchas

Hard-won facts about the ACP implementations we drive; check here before assuming the spec:

- Historical message editing uses a fresh `session/new` plus retained transcript context because standard ACP has no turn-addressed rewind. Never truncate only the UI while keeping the old peer context, and never replay historical tool actions as prompts. `AcpSession.editTurn` stages attachments and exact model/config/mode selections before replacing the local continuation; failed edited-turn retries rebuild that context. Workspace files are not rolled back. Verify Grok / Devin / Kimi capability boundaries with `scripts/probe-edit-turn.ts`.

- Model identity must preserve the ACP option ID and source/group identity, independently of the display name. Kimi's `kimi-code/k3` and `asgard/kimi-k3` both advertise `K3`; merging them by name routes selection to the first provider. Grok advertises custom config aliases such as `asgard` without source metadata, so `host/acp/modelSources.ts` reads custom endpoint declarations and `shared/modelSources.ts` annotates the options. Keep ACP select groups through normalization. New agent integrations must verify official/custom same-name selection, independent hiding, restoration, and config updates; unknown sources stay unclassified, and ambiguous duplicate parameter tuples remain separate by their original option IDs. Devin's genuine effort/Fast/1M variants still group normally.

- Grok echoes our prompt back as `user_message_chunk`; ignore it while a turn is in flight, and suppress content updates during load/resume replay
- Plan approval: Grok 1.0.18 sends `_x.ai/exit_plan_mode` with `planContent`, answered with `{ outcome: 'approved' | 'rejected' }` by `grokPlan.ts`. An unhandled method is misleadingly reported as a client disconnect. Devin and Kimi use `session/request_permission`; Devin marks plan writes/exits with `cognition.ai/isPlanFileEdit` / `cognition.ai/isExitPlan`, while Kimi puts the plan body in permission content. `plans.ts` preserves complete plan documents separately from the live to-do list. Verify with `scripts/probe-modes.ts`.
- Plan execution: `plan_document` cards stay outside process folds, preserve the file path and Markdown, and apply the chosen model before releasing approval. Model-switch failure leaves approval pending. Kimi 0.41.0 omits `current_mode_update` after approval; synchronize Default only after its successful ExitPlanMode output explicitly confirms deactivation. Grok's structured follow-up questions (`_x.ai/ask_user_question`) are a separate request handled by `questions.ts` (see the questions bullet); plan approval support does not imply question-form support and vice versa.
- Grok's first `tool_call` packet carries only `title` (e.g. `"read_file"`); kind/locations arrive in later `tool_call_update`s. A target inferred from the title is a fallback only — never overwrite rawInput/locations
- The SDK's `ctx.request(method, params)` generic inference is fragile: when params is a separate variable, annotate it explicitly as `acp.XxxRequest` or it silently degrades to `unknown`
- Permission requests usually carry only `toolCall.title`; get the command/verb from the corresponding tool call
- Controls are not hardcoded into "model / mode" buckets: `modes` come from `session/new`; every other select-type configOption goes into `controls.options` (ordered by category: model → thought_level → model_config → rest), rendered through the shared Composer presentation adapter and switched via `setConfig(configId, value)`; native `thought_level` selects join the model panel footer instead of creating separate toolbar chips. A `category=mode` configOption only stands in as modes when the protocol didn't send any (legacy Grok path); when modes exist it's a duplicate (Kimi sends both) and stays out of the control list
- Grok does not advertise modes in the protocol, but CLI ≥ 0.2.117 accepts `session/set_mode`, so the registry declares synthetic modes (`AgentDef.modes`): default / plan go over the protocol, yolo is host-side auto-approval of permissions while the CLI stays in default; `AcpSession.applyControls` backfills when the protocol gave no modes.
- Grok 1.0.18 advertises standard `reasoning_effort` / `thought_level` selects when the active catalog entry declares `reasoning_efforts`; `session/set_config_option` accepts a string value. The official grok-4.6 catalog has xhigh / high / medium / low. A custom alias without that declaration omits the select and rejects effort changes with -32602 (`unknown reasoning_effort value`). Synthesizing a client control cannot fix the CLI gate, and legacy `session/set_model` can acknowledge an ignored `_meta.reasoningEffort`. Declare supported efforts in the CLI model config; never infer successful application from acknowledgement alone. Verify with `scripts/probe-controls.ts` and `scripts/probe-controls-host.ts`.
- Grok 1.0.18 does not emit standard `usage_update`. Its prompt `_meta.usage` is aggregate spend across model calls and subagents, not current context occupancy. `grokUsage.ts` reads `_x.ai/session/info` → `result.context.used` / `total`, the same snapshot as the CLI context view. Refresh on start/resume, model selection and prompt completion before automatic compaction; prefer standard usage notifications when available. Invalid/unsupported snapshots stay unknown, and stale responses cannot replace newer usage. Kimi 0.41.0 asgard/kimi-k3 already advertises thinking low / high / max and emits `usage_update` asynchronously after the prompt response; keep probe processes alive for that notification. Switching models appends the previous thinking value when the new model does not offer it (K3 grows a leftover `on`, K2.7 a leftover `high`; DeepSeek legitimately mixes `off` with low / medium / high / max). `composerControls.presentReasoning` drops the stranger, renders `off` as a Thinking switch rather than a radio sibling, and `AcpSession.syncThought` writes a native value so the leftover does not stay on the wire.
- Follow-ups sent while a turn runs are a host-side queue (`AcpSession.queued`, in-memory, in send order): each entry is staged the moment it is queued (`preparePrompt` writes the blobs, per-draft problems are reported once) so `SessionView.queued: QueuedPrompt[]` carries `Attachment`s the webview renders like a sent turn's; `flushQueued` hands the staged payload to `prompt` (`StagedSend`, `edited` only for `editTurn`). `dequeue` / `editQueued` (kept attachments by index + new drafts, replaced in place) address entries by id; `chat/Queue.tsx` shows one row per entry above the composer with a pencil (inline bare Composer) and a bin
- Sessions belong to a project: `SessionRecord.cwd` / `SessionSummary.cwd` is the workspace folder the session was opened in (also the agent's working directory; `homedir()` without a folder). `acpira.sessionScope` (`workspace` default | `all`, `shared/settings.ts` `SessionScope` / `inWorkspace`) decides what the list shows: the webview filters `SessionList` by `InitState.cwd` (the active session always stays listed; the scope chips at the end of the filter row write the setting through `setSetting`, the settings General page has the same select), and the host consults `ManagerDeps.scope` for the picks a viewer makes on its own (`mostRecent()` at `attach({ mostRecent })`, the next session after `deleteSession`) so a sidebar never lands on another project's conversation. Under `all`, rows from other projects carry `projectName(cwd)` (faint, `max-w-project`) before the time and a `FolderInput` "move here" hover action → `moveSession` (`SessionManager.moveSession`): a stored record is patched, a live idle session is disposed and reopened in the new folder through `selectSessionFor` (the agent is respawned there, `session/resume` / `load` carry the new cwd, unknown-id fallbacks apply), a running one refuses with `host.moveWhileRunning`. `lab/session-scope.preview.html` shows the chips / tag / move; `test/SessionManager.test.ts` "workspace scope" covers the host side (project folders must exist — the fake agent is spawned in them)
- Session deletion is soft: `SessionManager.deleteSession` removes from the list and moves the record + blobs into `sessions/trash/` for 30 s (out of the live directory, so no other window's reconcile lists it); the webview shows an undo Toast; `restoreSession` moves them back, files are really deleted on timeout or dispose, and `init` sweeps trash entries older than the window (a crash's leftovers) while leaving fresh ones another host may still undo. Deletion wins over another window that has the same session live: `TranscriptStore.write` refuses to recreate a record the store once had on disk (`knew`) and that is gone, and `SessionManager.syncIndex` treats a live session missing from the reconciled list as deleted elsewhere (`forget` + `rehome` its viewers, toast). Verify with the "live in two managers" test
- Queue UI siblings use role-prefixed keys (`plan:<sessionId>`, `queue:<sessionId>`, `composer:<sessionId>`). Sharing a session-only key leaves orphaned queue rows and duplicates them on deletion. `sendQueued` prioritizes the existing staged entry, cancels the active turn, and lets prompt completion flush it; never send a concurrent ACP prompt from the cancel notification response. Repeated send-now clicks are ignored while cancellation is pending. Verify the real App routing in `lab/queue.preview.html` and cancellation / attachment order in `test/AcpSession.test.ts`.
- Devin credentials are a long-lived API key (`windsurf_api_key` from a PKCE login) stored at `~/.local/share/devin/credentials.toml`. With `ACP_BACKEND` set, `devin acp` only accepts credentials handed over by the host (the registry sets `ACP_BACKEND=windsurf`): `session/new` fails with -32000 until `authenticate({ methodId, _meta: { api_key, api_server_url } })` — any advertised methodId works if `_meta` has the key
- Devin's browser login (`devin-browser`) authenticates only the current process: the response is `{}`, the key is never returned or persisted. Durable accounts come from the toml only: import the local login, or run `devin auth login` in an isolated XDG directory (needs a TTY, so it runs in a VS Code terminal with file polling)
- `devin auth status` reads only the toml (ignores `WINDSURF_API_KEY`); delete `ACP_BACKEND` from the env before running it or it reports "Not logged in"
- Devin quota is not on the ACP wire: `/usage` is TUI-only (`Unknown command` over ACP) and `/session-stats` is per-session. The CLI reads it from the Windsurf seat service, a Connect RPC that also answers JSON: `POST {api_server_url}/exa.seat_management_pb.SeatManagementService/GetUserStatus` with `{ metadata: { apiKey, ideName, ideVersion, extensionVersion } }` (all four required, else 400; a bad key is 401). `userStatus.planStatus` carries `dailyQuotaRemainingPercent` / `weeklyQuotaRemainingPercent` (whole numbers) and `*QuotaResetAtUnix` (int64 as strings); `planInfo.hideDailyQuota` / `hideWeeklyQuota` say which windows the plan has (Max: weekly only, Pro: both). proto3 JSON omits zero fields, so on `billingStrategy === 'BILLING_STRATEGY_QUOTA'` a missing percent is 0%, not a missing window. `DevinAccountProvider.quota` → `AccountManager` cache (30 s max-age, forced after each turn of a bound session) → `AccountInfo.quota` → `ui/QuotaBars` in the account menu / settings rows
- Per-agent memory of the last chosen mode / config values lives in `~/.acpira/sessions/prefs.json` (`SessionManager.remember` on user `setMode` / `setConfig`, plus `rememberMode` when a ready session's mode changes on its own — Devin's "switch to bypass mode" permission answer arrives as `current_mode_update`, never through `setMode`); `newSession` replays it through `AcpSession.adoptControls` after `start`, one `set_config_option` per differing value in control order (model before effort), skipping values the agent no longer offers. Restored sessions keep their own persisted controls; `editTurn` restores exact per-turn settings and does not touch the memory
- Accounts are bound per session: one agent process uses one credential; switching accounts = starting a new session. `SessionRecord.accountId` is persisted so restored sessions keep their original account
- Auto-compaction: ACP has no compact request, so we use the agent's `/compact` slash command (Devin / Grok both expose it in `available_commands_update`). The host does not own the agentic loop and cannot inject compact mid-`session/prompt`. When `usage.used ≥ acpira.compactAtTokens` (default 300k) and `acpira.autoCompact` is on, `AcpSession.prompt` sends `/compact` after `end_turn` before flushing the queue, and again before the next non-auto prompt if usage is still over. The context panel shows the agent window, the budget marker, and that compact waits for the next ACP request. Devin reports `compaction_update` (in_progress → completed), normalized into a single `compaction` block
- Background compaction: Devin 3000.6.14 and Kimi 0.41.0 acknowledge manual `/compact` before it finishes, using plain-text completion messages; Devin can acknowledge before its first status notification. `compaction.ts` holds the host queue until completion, cancellation, or failure, and also tracks structured `compaction_update` IDs. Releasing on the RPC response alone cancels Devin's compaction or loses Kimi's follow-up reply from the ACP stream. Grok 1.0.18 waits inside the request. Verify with `scripts/probe-compaction.ts` and `scripts/probe-compaction-queue.ts`.
- Devin sweeps empty sessions that never received a message when the creating process exits: `session/load` then returns `-32016 Session not found`. `AcpSession.openSession` catches this and falls back to `session/new`; other load failures still go readonly. Another common errorKind is `session_locked` (-32015, retryable: another process holds the session) — that one is not downgraded
- Devin background shells: an `exec` (kind execute, `rawInput.command` / `timeout`) that outlives its timeout is parked, not finished — a `tool_call_update` keeps `status: in_progress` and adds `_meta['cognition.ai/background'] = true`, `cognition.ai/backgroundShellId`, `cognition.ai/backgroundCommand`; the call stays in_progress until the process exits (`_meta.terminal_exit`), and its output lands on that exec's `content`. Later `get_output` (title `Read shell`, **no kind**, `rawInput { shell_id, timeout }`, `_meta['cognition.ai/inferenceToolName'] = 'get_output'`) blocks for up to its timeout waiting on that process; `kill_shell` is `Kill shell` with the same shape, `write_to_process` arrives as kind execute titled ``Wrote to `cmd` ``. Rendered generically this read as `正在调用工具 shell` for minutes and was mistaken for a hang (one such session was cancelled and told to continue for no reason). `normalize.ts` marks the parked exec `background` (skipped by `activityOf` / `foldActivity`, so a streaming thought wins), and gives `get_output` / `kill_shell` `verb.wait` / `verb.kill` with the parked command as target via `NormalizeState.shells` (shell id → command, in-memory). Verify with `scripts/probe-questions.ts devin "<prompt asking for a backgrounded sleep + get_output>"`
- `promptCapabilities.image` is not authoritative: Grok advertises `image: false` yet accepts inline `{ type: 'image', data, mimeType }` blocks in `session/prompt` and the model really sees the pixels (Devin / Kimi advertise `true`). Never gate image sends on the flag; `pnpm probe <agent> --image PATH "describe it"` verifies. Grok also echoes the image block back as a `user_message_chunk` with `content.type === 'image'`, so user chunk handling must tolerate non-text content. All three advertise `embeddedContext: true`
- `getConfiguration().get()` returns a read-only Proxy: it cannot be `structuredClone`d or `postMessage`d (`#<Object> could not be cloned`) — round-trip through JSON first
- A failed `session/prompt` does not change the session status: `AcpSession.prompt` catches the JSON-RPC error and `failTurn` puts it on the turn (`AgentTurn.stop = 'error'`, `AgentTurn.error = { message, code, kind, retryable }`); `stopReason` other than `end_turn` / `cancelled` lands on `AgentTurn.stop` too. Devin's typed cause is `data['cognition.ai/errorKind']` / `data['cognition.ai/retryable']` (the same fields as the -32015 / -32016 load errors). The webview shows the last turn's short stop as a card above the composer (`chat/Alert.tsx`, dismiss is webview-local) plus a faint closing row in the message; `retryTurn` drops both turns and re-sends the user turn with drafts rebuilt from the blobs (`restoreDrafts`). Only `-32000` still flips the status to `auth_required`
- Questions (the agents' ask-user-question tools) all land in `host/acp/questions.ts` (`QuestionGate`) as one `QuestionBlock` in the current agent turn; the webview pins the open card above the composer (`chat/Questions.tsx`, Cursor's layout: lettered options, `Other…`, Skip / Continue, `1 of N` pager) and answers with `answer { blockId, answers, skip }`; a resolved block stays in the message as the `QuestionRecord` (`outcome` answered / skipped / cancelled + `answers`). Three dialects, verified with `scripts/probe-questions.ts` (raw wire) and `scripts/probe-questions-host.ts` (AcpSession path):
  - Devin 3000.6.14: `ask_user_question` is gated on the client's `elicitation.form` capability (without it the model asks in prose). Flow: `tool_call` (`_meta['cognition.ai/inferenceToolName'] = 'ask_user_question'`, `rawInput.questions[{ header, question, options[{ label, description }] }]`) → `elicitation/create` `mode: 'form'` **without** `toolCallId`, `message` = first question, `requestedSchema.properties.qN` = `{ title: header, description: question, oneOf: [{ const: label, title: description }] }` (label in `const`, description in `title` — the opposite of the spec's reading), all `required`, `_meta['cognition.ai/allowOther']`. `accept` with every key → `tool_call_update` `_meta['cognition.ai/answers']` then `completed`; free text comes back as `Other, <text>`; `accept` with keys missing is treated like `decline` ("The user wants to clarify these questions", tool `failed` with `cognition.ai/rejected`); `cancel` → "User canceled the question"
  - Kimi 0.41.0: same `elicitation/create` form **with** `toolCallId`; `properties.qN` = `{ title: header, oneOf: [{ const: label, title: label }] }` and no `description` — the question texts are joined with `\n` in `message`. Partial `accept` is fine (missing keys are simply unanswered), a string outside `oneOf` is dropped, `decline` / `cancel` → `{"answers":{},"note":"User dismissed the question without answering."}`
  - Grok 1.0.18: a private request `_x.ai/ask_user_question` `{ sessionId, toolCallId, questions[{ question, options[{ label, description }], multiSelect }], mode }` (an unhandled method fails the tool with method-not-found); the response is tagged on `outcome`: `{ outcome: 'accepted', answers: { [question]: label | string | string[] } }` (free strings allowed, unanswered questions simply omitted; `{}` yields the awkward "User has answered your questions: ."), `{ outcome: 'skip_interview', partial_answers? }` ("proceed with the information you have", answers listed with `(No answer provided)`), `{ outcome: 'chat_about_this', partial_answers? }` ("ask them what they would like to clarify"). The model sometimes claims the tool is unavailable and asks in prose instead — that is not a client failure
  - Mapping: Continue → Grok `accepted` / form `accept` (typed: boolean, number, string[]); Skip → Grok `skip_interview` + `partial_answers`; a form with some answers is `accept`ed as far as it goes, an untouched one is `decline`d; Stop / turn end → `cancel`. `QuestionGate.rememberToolInput` keeps `rawInput.questions` per tool call so form choices get the agent's own labels / descriptions (Devin's form has no `toolCallId`: the latest input with the same question count is used); `formQuestions` also handles `boolean` (Yes / No), `array` (`items.anyOf` / `enum`, multi-select), `enum`, `number` / `integer` (numeric text) and plain `string` (text). Tool rows titled `ask_user_question` / `AskUserQuestion` / `Ask(ed|ing) … questions` get `verb.ask` and drop the title target
- The live to-do list is `chat/PlanBar.tsx`: the latest `plan` block in the transcript (each update replaces the whole list), pinned above the composer while it has open entries; a fully completed list stays only until that same turn ends and must not reappear just because a later prompt is running; the `plan` block inside the message is the history copy. `plan_update` / `plan_removed` (ID-addressed, items / markdown / file) are only sent to clients advertising `clientCapabilities.plan`, which the extension does not, so agents keep sending the legacy `plan`
- Kimi's `session/new` auth gate (`ensureAuthed`) checks only the provider behind `default_model` in `~/.kimi-code/config.toml` (api_key set, or a cached OAuth token), then falls back to "any OAuth provider logged in". It does not care which model the session will use, so a working custom provider (`asgard`, …) still gets `-32000` when `default_model` points at `managed:kimi-code` and its OAuth cache is empty; fixes are `kimi login` or pointing `default_model` at the custom provider's model. `kimi acp` takes no `-m`, but `KIMI_CODE_HOME=<dir>` swaps the whole config dir (`pnpm probe kimi` with it verifies). The reason is only on stderr (ndjson `{"msg":"acp: auth readiness probe failed…","error":"provider … has no credential configured"}`), which is why `AcpSession` keeps the last auth-related stderr line and shows it in the Notice

## Conventions

- Official CLI quota monitoring is read-only: `host/accounts/local.ts` reads Grok `auth.json` and Kimi `credentials/kimi-code.json` / `device_id`, or an explicit `KIMI_CODE_API_KEY`. `LocalAccounts` publishes safe metadata through `AgentInfo.localAccount`; it never imports a switchable account or changes a session's credentials. Grok uses `cli-chat-proxy.grok.com/v1/billing?format=credits` plus `/v1/settings`; only explicit `creditUsagePercent` makes a bar, and on-demand balances are separate. Kimi uses `api.kimi.com/coding/v1/usages` for weekly and advertised short windows; custom endpoint overrides disable official credential reuse. Missing or expired credentials and unavailable percentages stay explicit states. Refresh on startup, after turns, and every minute while an account view is open; requests deduplicate and cache for 30 s. `ui/AccountLabel` shares the inline identity / plan layout, and `ui/QuotaBars` places the period, compact reset countdown badge and remaining percentage above a colored tube. Healthy allowance is green, at or below 30% amber, at or below 10% red. Multiple windows sit side by side in wide rows and stack in narrow views. Research references: [CodexBar Grok](https://github.com/steipete/CodexBar/blob/main/docs/grok.md), [CodexBar Kimi](https://github.com/steipete/CodexBar/blob/main/docs/kimi.md). Verify parsers and credential boundaries with `test/localAccounts.test.ts`; current-machine missing logins are not live quota success.

- Write code comments in English
- Components must not contain raw numbers: sizes, type scale, spacing, and radii all use token classes (`h-ctl`, `px-pad`, `gap-gap`, `rounded-md`, …)
- Every "row" (thought / plan / tool / status / session item) uses `ui/Row`; command execution is a row too (command on the row, output card below), not a separate block
- `ui/Button` has exactly two tiers, settled in the buttons LAB (`#page=buttons`): `primary` is a tonal grey fill (strong text, medium weight, firmer outline), `secondary` an outline that fills on hover. One primary per card (the action to take: allow-once, import login, the first sign-in method), everything else secondary — no third "ghost" tier, and the inverted solid (`--btn-1-*`) belongs to the send button alone. Agent-supplied sign-in method names are English on the wire; `notice.method.<agent>:<methodId>` keys localize the known ones (Notice falls back to the agent's name via `tOr`)
- The turn's top-level activity owns the only `Orb` (thinking-orbs), with a stable Working label throughout active execution, independent of folding and the latest tool. Initialization reuses the Orb with its built-in `connecting` state; turn activity uses `breathing`. The connecting label stays stable and the status row fades in together. Approval and question waits use static icons and their waiting labels. Expanded thought rows keep static icons, show Thinking with shimmer while streaming, and retain expandable text after completion. Empty streamed text adds no second waiting indicator. In-progress tool rows use the same static icon as their completed state plus a `shimmer` on the verb — never an Orb. The one spinner is the session list's `working` state (`LoaderCircle` + `animate-spin` in the time slot): a list item has no verb to shimmer, and a dot reads as "unread". Streamed prose and thought text use a per-grapheme fade with a slight downward entrance, a 320 ms visual backlog cap, and a 700 ms finish window. Incoming chunks render immediately without batching. Live row slots enter in sequence; restored history stays static. Rail growth is eased in JS by `ConnectedRail` (a CSS transition retargeted every frame stalls on the main thread), and motion-off / reduced-motion settings snap it instead. The stream and row animation rules live in `styles/motion.css`.
- Rail rule: indented disclosure bodies and tool result rows share `ui/ConnectedRail`. The solid line attaches to the actual icon strokes, ends with a short solid dot, and grows with streamed content. Result rails stop at the final row before its output card. Full-width diff / output cards and process fold bodies get no outer rail. Thought text renders `trimEnd()`ed: models close thoughts with `\n\n`, and under `whitespace-pre-wrap` those blank lines push the end dot below the text (`lab/thought.preview.html` → `trailing`)
- User prompts (`chat/HistoryMessage`) stick within their exchange and have no hover actions — clicking the card opens the inline editor, which is also where the full text is copied from. Once stuck at the top the text folds to `--user-message-stuck-lines` (3) with a `scroll-fade` edge and `overflow-hidden` (the wheel keeps moving the conversation); the stuck state comes from an `IntersectionObserver` sentinel at the exchange's top (`section` is `relative`, the scroller carries `data-thread`), and the sticky frame freezes its natural height via `min-height` while folded so the flow never shifts under the reader — the freed area is transparent and `pointer-events-none`. A hidden sidebar webview collapses the thread to no box: ignore those observer/scroll records and re-check when it has a box again, or coming back leaves a still-visible prompt folded as if the history had been compressed. Verify with `lab/history.preview.html?long`
- Scrollbars are overlay-style everywhere: `scrollbar-gutter: stable` keeps layout still, the track is transparent, and the hairline thumb shows only while its element scrolls (`ui/useScrollReveal` on the shell roots stamps `data-scrolling` for 800 ms) or under the pointer — never on focus. `scroll-thin` is the 6px variant for lists and card text. All scrollbar rules (including `.scroll-thin`, a plain class rather than an `@utility`) are unlayered in `base.css`: the host webview stylesheet paints `::-webkit-scrollbar-thumb` / `:hover` / `:active` with `--vscode-scrollbarSlider-*` unlayered, so a layered rule loses and every scroller grows a permanent grey bar. `lab/webview-defaults.css` replicates those host rules; import it in any LAB page that judges scrollbars
- To-do presentation separates history from the live dock: `chat/Plan` is a lightweight disclosure with a stable title, done/total and chevron; its entries expand to natural height without a card or current-task summary. `PlanBar` uses a two-level `PlanCard`: stable title/count on top, current task below while collapsed, replaced by the full `PlanEntries` list when expanded. The current task appears once per view. Only the dock list is height-limited and uses `useScrollFade`; each disclosure keeps its own state across plan updates.
- Process prose uses `--process-prose-gap` around action boundaries; consecutive tools retain `--process-row-gap`. Expanded process history stays in the conversation scroll flow, while thoughts retain their bounded viewport.
- Folding (`acpira.appearance.fold`, default `codex`): `codex` keeps one process fold per turn with tool calls, collapsed by default; turns without tool calls render normal thought / text / status blocks directly, retaining thought bodies without an enclosing duration fold; the head keeps the Working label and Orb while running, including when expanded, and shows `用时 4 分钟 46 秒` after completion. Manual expansion survives updates and completion; grouped tool outputs start collapsed. Process prose and resolved question records stay inside at their chronological position (a record hoisted after the fold reads as if the answer arrived after every later action), trailing reply text and permission cards stay outside. ACP does not distinguish commentary from final text, so trailing text moves into history when another action arrives. Duration uses `AgentTurn.startedAt` / `endedAt`, never summed thought durations; older turns without timestamps show `已完成`. `cursor` folds only runs of read-only actions. Fold bodies are not indented
- Appearance axes: the combo code is positional (`encodeAppearance`), so new axes go at the end of `AXES`; baseline is `201110200302100`. Only `motion` is exposed to users (settings → Appearance, over `setAppearance` → `acpira.appearance.motion`); the rest stay LAB decisions
- User-facing rendering preferences are plain `acpira.*` settings (`theme` / `uiFontSize` / `codeFontSize` / `diffMarkers` / `fontSmoothing`, sanitized in `shared/settings.ts`) shown on the settings Appearance page. `webview/look.ts` turns them into root attributes (`lookAttrs`: `data-theme-fixed`, `data-diff`, `data-smoothing`, inline `--ui-font-size` / `--code-font-size`) that both shells spread after `appearanceDataAttrs`; the LAB omits `look` so defaults paint. Theme: `resolveTheme` in `App` maps `auto` to `useVsCodeTheme()` (body's `vscode-*` class) and a fixed scheme sets `data-theme-fixed`; the host-derived roles in `tokens.css` (`--fg-1`, `--bg-0`, `--line-strong`, `--focus`) go through `--host-*` indirections that the fixed rule sets to `initial` (guaranteed-invalid → the `var()` fallbacks paint), otherwise a light shell would keep VS Code's dark sidebar background. Components read the resolved scheme from `ThemeContext` (`useTheme`), never from the body class. Type scale: `--text-*` are declared on `:root, .acp-shell` in terms of `--ui-font-size` / `--code-font-size` — a custom property resolves where it is declared, so the shell's inline override only reaches tokens redeclared on the shell; density / settings line heights are `calc(var(--ui-font-size) + Npx)` offsets, keep new sizes that way. `data-diff="signs"` just blanks `--diff-add` / `--diff-del` (the lines already carry `+` / `-` / space prefixes from `host/acp/diff.ts`)
- Interactive primitives use `@base-ui/react` through the split parts in `ui/Popover`, `DropdownMenu`, `Command`, `Collapsible`, `RadioGroup`, `Switch`, and `Dialog`. Compose `Root / Trigger / Portal / Positioner / Popup` directly; never reintroduce `Menu items=[]`, `children(api)`, or `content(close)` wrappers. `PanelHeader`, `PanelFooter`, and `OptionContent` provide presentation only. Buttons, chips, rows, and cards use cva; `cn` merges Tailwind classes with the custom typography and spacing scales.
- Every overlay portal inherits `ShellLayerContext`. Positioners default to bottom/start, read the numeric `--pop-gap` and shell `--pad`, and shift horizontally inside the shell. Side flipping is explicit at the Permission menu. Menus are nonmodal; radio items close on selection. After the Base UI open lifecycle completes, menus focus the checked enabled item or the first enabled action for both pointer and keyboard opening. `onOpenChange` is a Base UI request callback; the composer's counter uses `onOpenLifecycle`, which pairs actual open mounts and cleanup, including unmount. Triggers recognize both `data-open` and `data-popup-open`.
- Model panels use inline `Command` lists with automatic highlight and a visible search field at 12 families/options. Selected rows retain their fill while highlighted, all rows reserve a check column when any is selected, and local `scrollTop` owns list positioning. Selecting a family closes the popup; changing effort/Fast/1M/Thinking keeps it open. Agent/account pages use RadioGroup rows; SessionList keeps its own drawer/search/rename behavior and never uses Command. Mention anchors to the composer field with no initial/final focus transfer. Unpositioned Mention rows cannot receive pointer events; only actual mouse movement changes the active hit, since layout-triggered enter events can occur under a stationary pointer. Context usage keeps hover delays of 120/250 ms and opens immediately on focus.
- `Collapsible.Panel` always keeps its DOM mounted and uses an inert grid transition when closed. Disclosure retains ConnectedRail, streamed text and row entrance ownership remain unchanged, and nested folds preserve state. The menu and settings switches share one primitive with separate skins. Image Dialog stays absolute inside the shell, preserves natural image size, and neither locks document scrolling nor transfers focus. Toast remains timer-driven because its eight-second lifetime must continue during hover, focus and window blur; its viewport stays in the Thread area above the composer.
- Menus: the options area holds only homogeneous option rows; unavailable items are greyed out, not hidden. Bars are `[lead square button] [text, entry with chevron when clickable] …spacer… [action square button]`, row-sized text (text-2), text only in the middle — icons live in lead / action (a lucide `svg` is `display: block` under preflight and wraps inside a truncating span). A sub-page (accounts) gets a `PanelHeader` navigation bar on top (back · title · action) and no footer; a top-level menu puts its entry / action in a `PanelFooter`. A small form tied to the selection (`ui/Field`: `RadioPills` / `SwitchRow`) may sit under the list in the footer slot
- Overlays pick a width tier (`Popover.Positioner width="sm | md | lg | xl"` → `--pop-w-*`) instead of sizing to content: mode → sm, agent / model / flat option → md, context usage → lg, session list → xl. Lists cap at `--pop-rows` (8) and use the `scroll-thin` bar. The one exception is the `@` mention list (`chat/Mention.tsx`): it is an inline completion, so it spans the composer field it completes
- Composer layout is shared across all ACP agents: only mode on the left; additional config options, context usage, the model with reasoning metadata, and send on the right. `shared/composerControls.ts` classifies native reasoning before any model-name heuristic; `chat/ModelPicker.tsx` uses the same Devin-style model panel for flat and grouped catalogs. Native reasoning selects and embedded model variants share `EffortField` / `RadioPills`; display labels normalize to Low / Medium / High / XHigh / Max while original config and option IDs remain unchanged. A model-less agent keeps reasoning in the same field behind a right-side chip. Agent IDs must not select a separate composer or layout.
- Question card (`chat/Questions.tsx`): pinned above the composer, always visible while waiting, with no collapse control. The header shows a stable title and page count; exactly one question is mounted at a time, using only its question text, never a category/numeral prefix. Option rows use `ui/Row`, the same text-2 scale as buttons, first-line-aligned key slots and a check for selected options. The Other option is an inline input in its own row; focusing or typing selects it, and multi-select retains the other picks. Picking an option stays on the page; Previous / Next navigate and Submit answers sends the complete retained response. Only long current-question content scrolls, with a short edge fade; header and actions stay visible. Tab and named keys retain native focus behavior, focused buttons retain native Enter activation, and composition/modifier keys never choose an answer. Letters / digits select, arrows focus options, brackets navigate, and Escape skips. The resolved `QuestionRecord` remains an independent disclosure, rendered in sequence where the question was asked.
- Toolbar chips: exactly one `solid` Chip per toolbar (the mode: glyph from `chat/modeIcons.ts` + name, never truncates); everything else is `quiet`. The toolbar row is an `@container`; below the `sm` tier (a 380 sidebar leaves ~324px) chips collapse per `Chip.narrow` — mode / agent keep only their icon, the model keeps only its text, carets go first — so the model name never gets squeezed to a letter (Cursor collapses its mode pill the same way; Devin's composer has no carets at all). Mode menu rows are single-line (glyph + name, description as `hint` tooltip). The model choice is one chip — family plus `meta` (params, faint), joined with spaces and no middle dots, e.g. `Claude Fable 5.1 Max Fast` or `K3 Max`. Provider/source names appear only in the expanded model list, never in the toolbar chip. The chip opens one panel: the family list (search / pin; picking closes) with the current family's params as a form underneath (effort as `RadioPills`, Fast / 1M as `SwitchRow`s, a lone Standard / Thinking pair as a Thinking switch; changes apply at once and keep the panel open). Devin's side pane laid out vertically, because a 380 sidebar has no room beside the list. Never show the params again inside the family rows
