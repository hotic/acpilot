# ACPilot

A chat shell for VS Code / Cursor that drives official agent CLIs (`grok agent stdio`, `devin acp`, `kimi acp`, or any ACP-compatible command) over [ACP](https://agentclientprotocol.com) (JSON-RPC over stdio). The shell owns UI, session organization, permission approvals, accounts, and context budget; model calls and agent execution stay in the CLIs.

## Commands

- `pnpm build` — host bundle (esbuild → `dist/extension.cjs`) + webview bundle (Vite → `dist/webview/main.{js,css}`)
- `pnpm typecheck` — two tsconfigs (`tsconfig.webview.json` covers `src/webview` + `src/shared` + the LAB in `src/lab` / `lab`; `tsconfig.host.json` the host; shared options in `tsconfig.base.json`); the root `tsconfig.json` is a solution file with `references` only, do not add `compilerOptions` to it. A source directory outside both `include` lists is neither type-checked nor alias-resolved by the IDE
- `pnpm test` — vitest; `test/fake-agent.ts` is a fake ACP agent built on the SDK that feeds events to `AcpSession` tests
- `pnpm probe grok [--auth] [--api-key-env VAR] [--import-local] [--image PATH] [--link PATH] [--embed PATH] [--elicit] [prompt]` — run `initialize` + `session/new` (+ one prompt, optionally with an inline image / `resource_link` / embedded `resource` block) against a CLI without VS Code; `--elicit` advertises form elicitation and prints / auto-answers `elicitation/create`. Use this first when debugging protocol issues
- `pnpm package` — build a `.vsix`

## Architecture

- `src/shared/transcript.ts` — normalized transcript shape, the single contract between host and webview; `SessionView` is the full state pushed to the webview
- `src/shared/protocol.ts` — `HostMsg` / `WebviewMsg` message contract; `src/shared/appearance.ts` — appearance axes
- `src/host/extension.ts` — `activate`: registers the secondary-sidebar WebviewView, editor WebviewPanel, commands, settings listeners
- `src/host/bridge.ts` — one bridge per webview (HTML + CSP); manager events are batched over 30 ms before pushing
- `src/host/SessionManager.ts` — session hub (live processes, summaries, active session); all webview actions enter here; must not import `vscode`
- `src/host/acp/` — `AgentRegistry` (built-in grok / devin / kimi + user-defined via `acpilot.agents`, binary probing), `AgentProcess` (spawn + ndjson + `acp.client`), `AcpSession` (state machine: start → resume | load | new → ready, with auth_required / readonly / error states), `normalize.ts` (`session/update` → blocks, pure functions)
- `src/host/store/TranscriptStore.ts` — `globalStorage/sessions` holds `index.json` + `<id>.json` + `<id>/` (attachment blobs, content-hash names), writes are debounced
- Attachments: the webview turns pastes / drops / `@` picks into `Draft`s (`webview/chat/drafts.ts`, `Mention.tsx`) and sends them with the prompt; `host/acp/attachments.ts` (`preparePrompt`) writes images and dropped text to the session's blob dir and builds the `ContentBlock[]` — text → inline `image` → embedded `resource` (uri = blob path) → `resource_link` (Explorer / `@` files; image files among them are read and sent as `image`). The turn keeps `Attachment`s (blob name / uri only); the webview loads blobs from `InitState.blobBase` (the sessions dir as a webview URI, added to `localResourceRoots`). `@` search is `host/files.ts` (`findFiles` cached 15 s, fuzzy-scored host-side) answered over `searchFiles` → `files`
- `src/host/accounts/` — account layer. `types.ts` (`AccountProvider`: importLocal / login / spawnEnv? / authenticate?), `AccountStore` (metadata → `globalStorage/accounts.json`, secrets → `SecretVault`: `context.secrets` in VS Code, `MemoryVault` in tests), `AccountManager` (import / terminal login / removal + two hooks for `AcpSession`), `devin.ts` (first provider). Must not import `vscode`
- `src/webview/` — React UI: `ui/` primitives (Row / Disclosure / Button / Chip / Card / Popover / Menu), `chat/` conversation components, `effects/` visual effects, `styles/tokens.css` design tokens
- `src/webview/` and `src/host/acp/` must never import `vscode`

## Protocol gotchas

Hard-won facts about the ACP implementations we drive; check here before assuming the spec:

- Grok echoes our prompt back as `user_message_chunk`; ignore it while a turn is in flight, and suppress content updates during load/resume replay
- Grok's first `tool_call` packet carries only `title` (e.g. `"read_file"`); kind/locations arrive in later `tool_call_update`s. A target inferred from the title is a fallback only — never overwrite rawInput/locations
- The SDK's `ctx.request(method, params)` generic inference is fragile: when params is a separate variable, annotate it explicitly as `acp.XxxRequest` or it silently degrades to `unknown`
- Permission requests usually carry only `toolCall.title`; get the command/verb from the corresponding tool call
- Controls are not hardcoded into "model / mode" buckets: `modes` come from `session/new`; every other select-type configOption goes into `controls.options` (ordered by category: model → thought_level → model_config → rest), one Chip per option in the Composer, switched via `setConfig(configId, value)`. A `category=mode` configOption only stands in as modes when the protocol didn't send any (legacy Grok path); when modes exist it's a duplicate (Kimi sends both) and stays out of the control list
- Grok does not advertise modes in the protocol, but CLI ≥ 0.2.117 accepts `session/set_mode`, so the registry declares synthetic modes (`AgentDef.modes`): default / plan go over the protocol, yolo is host-side auto-approval of permissions while the CLI stays in default; `AcpSession.applyControls` backfills when the protocol gave no modes. Grok's reasoning effort hides in `_meta.reasoningEfforts` (not a standard configOption) and is not wired up yet
- Session deletion is soft: `SessionManager.deleteSession` removes from the list and moves to a 30 s trash (files untouched); the webview shows an undo Toast; files are really deleted on timeout or dispose
- Devin credentials are a long-lived API key (`windsurf_api_key` from a PKCE login) stored at `~/.local/share/devin/credentials.toml`. With `ACP_BACKEND` set, `devin acp` only accepts credentials handed over by the host (the registry sets `ACP_BACKEND=windsurf`): `session/new` fails with -32000 until `authenticate({ methodId, _meta: { api_key, api_server_url } })` — any advertised methodId works if `_meta` has the key
- Devin's browser login (`devin-browser`) authenticates only the current process: the response is `{}`, the key is never returned or persisted. Durable accounts come from the toml only: import the local login, or run `devin auth login` in an isolated XDG directory (needs a TTY, so it runs in a VS Code terminal with file polling)
- `devin auth status` reads only the toml (ignores `WINDSURF_API_KEY`); delete `ACP_BACKEND` from the env before running it or it reports "Not logged in"
- Accounts are bound per session: one agent process uses one credential; switching accounts = starting a new session. `SessionRecord.accountId` is persisted so restored sessions keep their original account
- Auto-compaction: ACP has no compact request, so we use the agent's `/compact` slash command (Devin / Grok both expose it in `available_commands_update`). After a turn ends, `AcpSession.prompt` sends `/compact` when `usage.used ≥ acpilot.compactAtTokens` (default 300k) and `acpilot.autoCompact` is on. Devin reports `compaction_update` (in_progress → completed), normalized into a single `compaction` block
- Background compaction: Devin 3000.6.14 and Kimi 0.41.0 acknowledge manual `/compact` before it finishes, using plain-text completion messages; Devin can acknowledge before its first status notification. `compaction.ts` holds the host queue until completion, cancellation, or failure, and also tracks structured `compaction_update` IDs. Releasing on the RPC response alone cancels Devin's compaction or loses Kimi's follow-up reply from the ACP stream. Grok 1.0.18 waits inside the request. See `docs/compaction-queue.md` and the two compaction probe scripts for evidence and verification commands
- Devin sweeps empty sessions that never received a message when the creating process exits: `session/load` then returns `-32016 Session not found`. `AcpSession.openSession` catches this and falls back to `session/new`; other load failures still go readonly. Another common errorKind is `session_locked` (-32015, retryable: another process holds the session) — that one is not downgraded
- `promptCapabilities.image` is not authoritative: Grok advertises `image: false` yet accepts inline `{ type: 'image', data, mimeType }` blocks in `session/prompt` and the model really sees the pixels (Devin / Kimi advertise `true`). Never gate image sends on the flag; `pnpm probe <agent> --image PATH "describe it"` verifies. Grok also echoes the image block back as a `user_message_chunk` with `content.type === 'image'`, so user chunk handling must tolerate non-text content. All three advertise `embeddedContext: true`
- `getConfiguration().get()` returns a read-only Proxy: it cannot be `structuredClone`d or `postMessage`d (`#<Object> could not be cloned`) — round-trip through JSON first
- A failed `session/prompt` does not change the session status: `AcpSession.prompt` catches the JSON-RPC error and `failTurn` puts it on the turn (`AgentTurn.stop = 'error'`, `AgentTurn.error = { message, code, kind, retryable }`); `stopReason` other than `end_turn` / `cancelled` lands on `AgentTurn.stop` too. Devin's typed cause is `data['cognition.ai/errorKind']` / `data['cognition.ai/retryable']` (the same fields as the -32015 / -32016 load errors). The webview shows the last turn's short stop as a card above the composer (`chat/Alert.tsx`, dismiss is webview-local) plus a faint closing row in the message; `retryTurn` drops both turns and re-sends the user turn with drafts rebuilt from the blobs (`restoreDrafts`). Only `-32000` still flips the status to `auth_required`
- Devin's `ask_user_question` is gated on the client's `elicitation.form` capability: without it Devin does not even give the model the tool (the model asks in prose, no failure); with it the flow is `tool_call` (`_meta['cognition.ai/inferenceToolName'] = 'ask_user_question'`, `rawInput.questions`) → `elicitation/create` `mode: 'form'` whose `requestedSchema.properties.qN` has `title` (header), `description` (question) and the choices as `oneOf: [{ const, title }]` (not `enum`), `_meta['cognition.ai/allowOther']` → the answer `{ action: 'accept', content: { qN: value } }` → `tool_call_update` with `_meta['cognition.ai/answers']`, then `completed` with the answer as text content. `ClientHandlers.onElicitation` advertises the capability when present; the extension does not set it yet
- The live to-do list is `chat/PlanBar.tsx`: the latest `plan` block in the transcript (each update replaces the whole list), pinned above the composer while it has open entries or the turn runs; the `plan` block inside the message is the history copy. `plan_update` / `plan_removed` (ID-addressed, items / markdown / file) are only sent to clients advertising `clientCapabilities.plan`, which the extension does not, so agents keep sending the legacy `plan`
- Kimi's `session/new` auth gate (`ensureAuthed`) checks only the provider behind `default_model` in `~/.kimi-code/config.toml` (api_key set, or a cached OAuth token), then falls back to "any OAuth provider logged in". It does not care which model the session will use, so a working custom provider (`asgard`, …) still gets `-32000` when `default_model` points at `managed:kimi-code` and its OAuth cache is empty; fixes are `kimi login` or pointing `default_model` at the custom provider's model. `kimi acp` takes no `-m`, but `KIMI_CODE_HOME=<dir>` swaps the whole config dir (`pnpm probe kimi` with it verifies). The reason is only on stderr (ndjson `{"msg":"acp: auth readiness probe failed…","error":"provider … has no credential configured"}`), which is why `AcpSession` keeps the last auth-related stderr line and shows it in the Notice

## Conventions

- Write code comments in English
- Components must not contain raw numbers: sizes, type scale, spacing, and radii all use token classes (`h-ctl`, `px-pad`, `gap-gap`, `rounded-md`, …)
- Every "row" (thought / plan / tool / status / session item) uses `ui/Row`; command execution is a row too (command on the row, output card below), not a separate block
- `ui/Button` has exactly two tiers, settled in the buttons LAB (`#page=buttons`): `primary` is a tonal grey fill (strong text, medium weight, firmer outline), `secondary` an outline that fills on hover. One primary per card (the action to take: allow-once, import login, the first sign-in method), everything else secondary — no third "ghost" tier, and the inverted solid (`--btn-1-*`) belongs to the send button alone. Agent-supplied sign-in method names are English on the wire; `notice.method.<agent>:<methodId>` keys localize the known ones (Notice falls back to the agent's name via `tOr`)
- Motion is reserved for Thinking: the `Orb` (thinking-orbs) appears only while a thought streams (and on the connecting Notice); it swaps to a static icon when the thought ends. In-progress tool rows use the same static icon as their completed state plus a `shimmer` on the verb — never an Orb
- Rail rule: an expandable row whose body is indented past the lead slot (not full width — thought text, plan entries) gets a solid `rail` down that slot (built into `ui/Disclosure`); full-width bodies (diff / output cards, fold bodies) get none. Result lists (search / fetch hits) use the dashed `timeline` variant instead
- Folding (`acpilot.appearance.fold`, default `codex`): `codex` keeps one process fold per turn with tool calls, collapsed by default; turns without tool calls render normal thought / text / status blocks directly, retaining thought bodies without an enclosing duration fold; the head shows the current action while running and `用时 4分钟 46秒` after completion. Manual expansion survives updates and completion; grouped tool outputs start collapsed. Process prose stays inside, trailing reply text and permission cards stay outside. ACP does not distinguish commentary from final text, so trailing text moves into history when another action arrives. Duration uses `AgentTurn.startedAt` / `endedAt`, never summed thought durations; older turns without timestamps show `已完成`. `cursor` folds only runs of read-only actions. Fold bodies are not indented
- Appearance axes: the combo code is positional (`encodeAppearance`), so new axes go at the end of `AXES`; baseline is `201110200302100`
- Menus: the options area holds only homogeneous option rows; unavailable items are greyed out, not hidden. Bars are `[lead square button] [text, entry with chevron when clickable] …spacer… [action square button]`, row-sized text (text-2), text only in the middle — icons live in lead / action (a lucide `svg` is `display: block` under preflight and wraps inside a truncating span). A sub-page (accounts) gets a `MenuHeader` navigation bar on top (back · title · action) and no footer; a top-level menu puts its entry / action in a `MenuFooter`. A small form tied to the selection (`ui/Field`: `RadioPills` / `SwitchRow`) may sit under the list in the footer slot
- Overlays pick a width tier (`Popover width="sm | md | lg | xl"` → `--pop-w-*`) instead of sizing to content: mode → sm, agent / model / flat option → md, context usage → lg, session list → xl. Lists cap at `--pop-rows` (8) and use the `scroll-thin` bar. The one exception is the `@` mention list (`chat/Mention.tsx`): it is an inline completion, so it spans the composer field it completes
- Toolbar chips: exactly one `solid` Chip per toolbar (the mode: glyph from `chat/modeIcons.ts` + name, never truncates); everything else is `quiet`. The toolbar row is an `@container`; below the `sm` tier (a 380 sidebar leaves ~324px) chips collapse per `Chip.narrow` — mode / agent keep only their icon, the model keeps only its text, carets go first — so the model name never gets squeezed to a letter (Cursor collapses its mode pill the same way; Devin's composer has no carets at all). Mode menu rows are single-line (glyph + name, description as `hint` tooltip). The model choice is one chip — family plus `meta` (params, faint) — opening one panel: the family list (search / pin; picking closes) with the current family's params as a form underneath (effort as `RadioPills`, Fast / 1M as `SwitchRow`s, a lone Standard / Thinking pair as a Thinking switch; changes apply at once and keep the panel open). Devin's side pane laid out vertically, because a 380 sidebar has no room beside the list. Never show the params again inside the family rows
